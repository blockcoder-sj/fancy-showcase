# FANcy 보안 모델

## 보호하려는 것

FANcy의 목표는 티켓 QR 캡처, 계정 공유, 동일 티켓의 동시 입장, 권한 없는 스캐너 사용으로부터 입장 권리를 보호하는 것입니다. 휴대폰 자체가 완전히 장악된 상황이나 외부 카메라 촬영을 완벽히 막는다고 주장하지 않습니다.

## 핵심 통제

| 위협 | 통제 | 최종 판정 위치 |
|---|---|---|
| QR 캡처·전달 | 짧은 수명, 현재 QR 식별자 확인, 서버 상태 검사 | Ticket API |
| 같은 QR 동시 사용 | 조건부 상태 전이와 원자적 1회 입장 | Ticket Ledger |
| 계정 공유 | Google 신원 + 활성 기기 + 하드웨어 키 결합 | Auth + Ticket API |
| 소프트웨어 키 위조 | 원격 attestation 검증과 하드웨어 보호 수준 확인 | Attestation Verifier |
| 생체 승인 우회 | OS가 보호하는 키 사용 시 매회 생체 인증 요구 | Android/iOS secure key store |
| 기기·생체 보안 상태 변경 | 키 무효화 보고 후 관련 티켓 잠금 | Mobile + Ticket API |
| 관리자·스캐너 권한 상승 | 관리자·관계자·스태프 역할 및 게이트 할당 분리 | Web + Ticket API |
| 오래된 상태 재적용 | 단조 증가 상태 버전과 멱등 이벤트 처리 | Web projection |

## 하드웨어 키와 생체정보

지원 Android 기기에서는 티켓 개인키를 Android Keystore의 TEE 또는 StrongBox 경계에 생성하고 내보낼 수 없도록 요청합니다. 서버는 공개키와 attestation 결과를 저장하지만 지문·얼굴 템플릿은 받거나 저장하지 않습니다. 생체 비교는 운영체제 보안 UI와 하드웨어 경계에서 수행됩니다.

키는 단순히 생체 UI를 통과했다는 앱의 boolean 값을 신뢰하지 않습니다. 서버의 일회성 challenge를 해당 키로 서명해야 다음 단계가 진행됩니다.

## 생체 등록 변경의 의미

Android의 강한 생체 등록이 추가되거나 전체 생체 설정이 재설정되면, 기기와 제조사 정책에 따라 기존 인증 키가 영구 무효화될 수 있습니다. FANcy는 strict invalidation을 요청하고 Keystore가 무효화를 보고하면 관련 키를 폐기하고 티켓을 잠급니다.

운영체제가 개별 지문 한 개의 삭제를 항상 키 무효화 사건으로 제공하는 것은 아닙니다. 따라서 “모든 생체 목록 편집을 앱이 직접 감지한다”는 주장은 하지 않습니다. 실제 보안 경계는 OS가 보장하는 키 사용 가능 여부와 서버 원장 상태입니다.

## QR과 화면 캡처

릴리스 지갑은 화면 캡처 방지를 요청하지만 이는 보조 통제입니다. 외부 카메라와 OS 취약점을 완전히 막을 수 없으므로 QR 자체를 장기 자격증명으로 사용하지 않습니다. 입장 시 서버가 QR 만료, 현재 식별자, 티켓 활성 상태, 입장 시간, 사용 여부를 다시 확인합니다.

## 실패 닫힘

다음 상황에서는 QR을 발급하거나 입장을 승인하지 않습니다.

- 티켓이 활성 상태가 아님
- 현재 활성 기기 또는 기기 키가 일치하지 않음
- 키가 폐기·무효화되었거나 원격 검증 수준을 충족하지 못함
- challenge 또는 QR이 만료되었거나 이미 사용됨
- 입장 가능 시간이 아니거나 스태프가 해당 게이트에 배정되지 않음

## 공개 자료의 한계

이 문서는 방어 원리와 신뢰 경계를 설명합니다. 키·토큰 형식, 운영 비밀값, abuse threshold, 취약점 재현 절차는 공개하지 않습니다. 또한 자동 테스트와 자체 실기기 검증은 독립 보안 인증이나 프로덕션 안전성 보증을 대체하지 않습니다.
